# 逐页检查与检查说明

每页在本次用户任务中只有一次生图机会，失败或结果未知也占用次数。检查用于如实说明结果，不触发自动修正、技术重试、候选生成或版本择优。最多 10 个未结束请求，已有任务更低的并发上限继续生效；仍在运行或结果未明时等待、找回原调用，不重新提交。

## 一次客观基础对照

保存生成图后，与已载入的源页做一次基础对照，不重新渲染 PDF 或开展反复检查。关注可见内容及主要区域关系：明显漏译、遗漏或重复，图表和图注归属、公式和重要字段的明显变化，遮挡、截断，以及各栏首末位置、连续段落占位和新增空白。原有空白、正常中文换行与明显整栏收缩须根据源图区分；不能仅凭空白推断漏译。

按规则保留的公式、人名、缩写和无法可靠辨认的源文字不算漏译。顺带发现的明确内容错误须记录，但不增加 OCR、预翻译、页面分类、逐字审校或第二轮检查。

描述实际看见的位置和现象；看不清时明确写不确定，不猜测原因。局部疑点不能掩盖同页另一处已确认的问题，两者都保留。检查说明应简短，但不省略已确认的实质问题；不评分，不判断页面是否值得重新生成，也不宣称内容无错。

## 内部记录

已生成页面的内部评审只需 `status` 和非空的 `observations` 字符串数组：

- `pass`：已完成基础对照，未见明显问题。
- `issue`：发现明确问题；同页仍可另记局部疑点。
- `unknown`：尚不能形成有效判断，或只有未能确认的疑点。

每条观察写明位置与现象或具体不确定之处。不要输出空观察数组或虚构检查结果。新记录不需要 `severity`、`retry_eligible`、`evidence`、`impact`、`correction` 等修正判定字段；历史记录兼容由页面脚本处理，不手工重置调用历史。

未生成页依据调用及文件状态说明原因，不伪造图像检查记录。运行中的调用仍等待原结果，不能为了完成说明而记作确定失败。

记录格式示例，不代表实际页面结论：

```json
{
  "status": "issue",
  "observations": [
    "右栏中下部连续段落占位明显缩短，原正文区域出现新增大块空白；未据此推断漏译。",
    "公式（1）的下标太小，无法确认是否与源图一致。"
  ]
}
```

## 《逐页检查说明.md》

与 PDF 一并交付该 Markdown 文件。正文由一条范围说明和一个三列表组成：**原页码 / 检查结果 / 位置与说明**。范围说明列出本次交付范围的 PDF 实际原页序，说明检查版式、内容区域及可直接确认的文字问题。初次交付按所选原页序每页一行，包括缺失页；合并用户更新后，MD 仍覆盖基础任务的整份交付范围，不仅列本轮更新的页。不要将部分 PDF 的输出页序误当成原页码。

检查结果只使用以下四种文字，分别对应已记录的情况：`未见明显问题`、`发现问题`、`待确认`、`未生成`。前面三种对应实际交付图片的 `pass`、`issue`、`unknown`；仅没有可交付图片的页标 `未生成`。更新失败但沿用已有图片时，保留旧图的检查状态，并在说明中附“本次更新未生成，沿用原结果”；后续该页再更新成功时，改用新图检查结论，不带入过时的失败提示。每页的多项说明用分号合并在同一行，包含已确认问题与局部疑点；不要新增评分、重做建议、调用统计或择优结论。

下例仅示意格式，生成实际说明时须替换为真实页码与观察：

```markdown
范围：PDF 原页序第 1–4 页；检查版式、内容区域及可直接确认的文字问题。

| 原页码 | 检查结果 | 位置与说明 |
| --- | --- | --- |
| 1 | 未见明显问题 | 主要内容与区域关系保留，未见明显正文收缩或新增大块空白。 |
| 2 | 发现问题 | 右栏中下部连续段落明显收缩，原正文区域新增大块空白；公式（1）下标太小，无法确认。 |
| 3 | 待确认 | 左栏底部小字无法可靠辨认，未能确认与源图是否一致。 |
| 4 | 未生成 | 原调用已确认失败，未取得可用图片。 |
```

## 用户选择后再优化

只有用户随后明确选定要优化的页面，才为该新一轮任务执行每页一次生成，并附上用户给出的要求。仍以原 PDF 页面图为事实和版式基准；检查说明用于帮助用户选页，不能据此自主挑页、扩大范围或再次调用。新一轮继续如实记录结果，保留既有生成图和历史记录。
