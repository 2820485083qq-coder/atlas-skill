# Book 3: Topic and Idea

Use this reference when the user has keywords, search results, or a literature library and needs grouping, tagging, topic generation, field understanding, or idea selection.

## Source Scope

Distilled from the `《科研论3：选题/找idea》` section of the Keyanlun column index and the five-step article's `分` explanation. The index emphasizes importing literature, coarse grouping, purpose-driven reading, common grouping mistakes, four types of topic origin, fine grouping, cross-domain transfer, and adapting grouping to humanities and other fields.

## Core Model

Ideas emerge from a structured corpus. Do not ask the user to "think harder" before the corpus has been searched, gathered, and grouped for a purpose.

Grouping is useful only when it serves one of these outputs:

1. Understand what people are doing.
2. Answer a concrete research question.
3. Compare multiple possible directions.
4. Identify experiments, theory, code, empirical designs, or analysis routes.
5. Troubleshoot failure or failed reproduction.
6. Build writing material for the final paper.

## Chapter-Level Method Cards

### Card 1: 目的导向型文献阅读

Use when the user has imported many papers and asks what to read.

Method:

1. Pick the reading scenario before opening papers.
2. Match reading depth to the scenario.
3. Treat grouping as "labeling for action", not as a library-beautification exercise.
4. Stop reading when the required output is produced.

Six common scenarios:

| Scenario | Reading Output |
| --- | --- |
| Does not know what to do | Coarse groups and candidate directions |
| Has a concrete question | Evidence about whether the question is solved |
| Several directions compete | Comparison table and selection criteria |
| Needs experiments/theory/code | Method/route library |
| Results fail or cannot reproduce | Failure-mode and troubleshooting groups |
| Needs paper writing | Text/hard-material library route for Book 5 |

### Card 2: 粗分

Use when the field is broad or the user is still looking for a direction.

Method:

1. Scan titles/keywords/abstracts for recurring expressions with medium frequency.
2. Create a group when the expression can help action.
3. Put unclear items in unclassified; do not freeze.
4. After each group, ask "what idea or next search does this open?"

Deliverable:

- First-level group list.
- Emerging direction list.
- Groups that deserve fine grouping.

### Card 3: 细分

Use when the user has a subdirection and needs a concrete plan.

Method:

1. Choose relevant coarse groups.
2. Split by object, condition, mechanism, method, metric, application, data, or failure.
3. Compare the resulting subgroups to find missing combinations or transferable methods.
4. Produce idea candidates and verification candidates.

Deliverable:

- Secondary tag table.
- Candidate idea table.
- Verification route candidates.

### Card 4: 四类选题来源

Use when the user asks what counts as an idea.

Method:

1. Curiosity: identify a puzzle worth explaining.
2. Real-world demand: start from a clinical/engineering/social/industrial need.
3. Accident: turn unexpected observations or failed attempts into questions.
4. Combination: combine object + method + mechanism + context from grouped literature.

Deliverable:

| Idea Source | User Evidence | Candidate Question | Needed Verification |
| --- | --- | --- | --- |

### Card 5: 跨领域迁移

Use when the user dismisses examples because they are from another field.

Method:

1. Extract the operation, not the domain content.
2. Identify the equivalent object/method/problem in the user's field.
3. Transfer the grouping or verification move.
4. Test whether the transferred move opens a usable idea.

Deliverable:

- Source-domain operation.
- Target-domain equivalent.
- Transfer risk.
- Test action.

## Topic Origins

Use these categories to avoid a narrow "copy a gap from papers" mindset:

- Curiosity driven: the user wants to explain something puzzling.
- Real-world demand driven: clinical, engineering, social, industrial, policy, or lived-world pain points create the research question.
- Accident driven: unexpected observations or failed attempts become the idea.
- Combination driven: object/method/problem/context combinations create a new route.

## Grouping Workflow

### 1. Decide Grouping Purpose

Ask: "What should grouping let us do next?"

If no answer exists, the user may still be at Book 2 search or Book 1 layer diagnosis.

### 2. Coarse Grouping

Use when the user does not know what the field is doing or has a large corpus.

Actions:

- Start with visible title/keyword/abstract patterns.
- Create a first group when a recurring expression is useful.
- Use frequency as a clue, not a final answer.
- Keep an unknown/unclassified bucket.
- Record why each group matters.

Output:

- First-level group table.
- Candidate direction signals.
- Groups to inspect next.

### 3. Fine Grouping

Use when the user has a subdirection and needs concrete plans.

Actions:

- Select relevant coarse groups.
- Split by research object, mechanism, method, data type, performance metric, failure mode, or application context.
- Compare groups to reveal open slots, method transfers, or Plan B/C.
- Avoid making groups mutually exclusive if non-exclusive tagging serves the output better.

Output:

- Second-level tags.
- Candidate ideas.
- Evidence and method source papers.
- Verification candidates for Book 4.

## Common Mistakes

- Grouping everything perfectly before using any group.
- Treating a method/tool as the research purpose.
- Only reading papers from the exact same field and missing transferable operations.
- Refusing cross-field examples because the domain differs.
- Starting writing material libraries before topic and verification are stable.
- Believing "I still cannot think of ideas" after only reading, when grouping has not produced outputs.
