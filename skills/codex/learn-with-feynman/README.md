# Learn with Feynman

一个轻量的 Codex Skill，用费曼学习法帮助你把“看起来懂了”变成“能够用自己的话解释和使用”。

它不会一上来就给出一篇完整讲解，而是先让学习者尝试解释，再定位最影响理解的一个缺口，通过追问、提示和新情境检验，帮助学习者重新组织自己的理解。

## 它解决什么问题

阅读资料或听完解释后，我们很容易产生“熟悉就是理解”的错觉。真正的理解需要能够脱离原文：

- 用自己的话说明概念；
- 讲清关键原因、关系或步骤；
- 发现自己停顿和含糊的位置；
- 在条件略有变化时继续正确推理。

`learn-with-feynman` 把这个过程组织成一段一次只处理一个问题的学习对话。

## 怎么工作

### 1. 定界

把宽泛主题缩小成一个几分钟内可以解释、可以检验的问题。

例如，不直接学习“AI Agent”，而是先弄清：

> AI Agent 和普通聊天机器人最关键的区别是什么？

### 2. 外化

学习者暂时放下资料，从记忆出发，用自己的话解释。不会的地方可以直接说不会。

### 3. 诊断

Skill 找到最早、最基础、最影响后续理解的一个断点，例如：

- 用未解释的术语替代机制；
- 只说结果，没有因果过程；
- 知道各个部分，却无法说明它们如何连接；
- 会背定义，但不能处理例子；
- 忽略了规则成立的条件或边界。

每轮只追问一个缺口，不一次罗列所有问题。

### 4. 重构

缺口修复后，学习者重新从头解释，并通过一个新例子、反例或轻微变化的情境检验理解。

```text
定界 → 外化 → 诊断 → 重构
              ↑       ↓
              └─ 新情境暴露缺口 ─┘
```

## 对话示例

你可以这样开始：

```text
$learn-with-feynman 我想理解 AI Agent。
```

Skill 不会马上把所有知识讲完，而会先缩小问题：

```text
这轮我们先弄清：AI Agent 和普通聊天机器人最关键的区别是什么？
讲清的证据是，你能解释这个区别，并判断一个新案例是不是 Agent。

先不要查资料。请用自己的话讲讲你现在认为两者有什么不同。
不会的地方直接说不会。
```

你也可以直接提供自己的解释：

```text
$learn-with-feynman 我来解释一下什么是机会成本，请检查我哪里没讲清楚。
```

## 什么不算真正讲清楚

- 只说“我懂，但不会表达”；
- 只背诵教材定义或重复 AI 的答案；
- 只列出一组专业术语；
- 只给类比，不解释真实机制；
- 用一个没解释的专业词替换另一个专业词；
- 只能识别正确选项，不能自己生成解释。

表达不够漂亮、顺序稍乱或有停顿，不会被自动判断为不理解。判断重点是机制、关系和推理是否成立。

## 什么时候适合使用

- 学习一个新概念；
- 检查自己是否真的理解；
- 感觉“好像懂了，但讲不清”；
- 找出解释中的知识盲点；
- 把复杂内容重新组织成白话；
- 用例子或新情境检验理解。

如果你只需要一个简短事实、翻译、摘要或代写结果，不需要启动完整的费曼学习流程。

## 安装到 Codex

将仓库中的 `learn-with-feynman` 文件夹复制到 Codex 的全局 Skills 目录：

```text
~/.codex/skills/learn-with-feynman/
```

安装后的结构应为：

```text
~/.codex/skills/learn-with-feynman/
├── README.md
├── SKILL.md
└── agents/
    └── openai.yaml
```

重新启动 Codex，然后使用 `$learn-with-feynman`，或直接说“用费曼学习法帮我理解……”即可。

这个版本只有 Markdown 和 YAML 文件，不需要安装 Python、Node.js 或虚拟环境。


`README.md` 面向使用者，介绍项目和安装方式；`SKILL.md` 面向 Codex，定义实际教学流程和判断规则。Codex 触发和执行 Skill 时以 `SKILL.md` 为准。

## 设计原则

- 学习者先解释，Agent 后介入；
- 一次只学习一个可检验概念；
- 一轮只处理一个关键缺口；
- 先追问，再逐级提示，最后才补充必要事实；
- 使用学习者自己的语言和例子；
- 用新情境检验，而不是用“听懂了吗”确认；
- 区分“本轮讲清楚”和“已经长期掌握”。
